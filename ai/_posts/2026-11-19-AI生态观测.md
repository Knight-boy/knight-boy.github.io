这个系列从[底层架构](/ai/2026-11-05-AI底层架构详解/)一路讲到[思考之谜](/ai/2026-11-10-AI的思考之谜/)，回答的都是“为什么”和“怎么做”。这一篇换个视角，抬头看窗外：2026 年的 Agent 生态，实际长成了什么样子？

素材是一份 GitHub 星数快照。它当然不是技术判断的全部，但当成千上万的开发者各自点下收藏，汇总出来的东西有它自己的信息量。

## 一、先说清楚：星数是一张注意力地图

GitHub 的星标本质是收藏：一个开发者觉得这个项目以后可能用得上，于是点一下。它既不是安装量，也不是使用量，更不是质量评分。一个项目可以靠一篇爆款文章一夜涨几千星，也可能在停止维护三年后仍挂着漂亮的总数。

所以读星榜之前，先把三个误读放下：

- **星数不等于用户数**：收藏和真正跑起来之间，隔着一次安装、一次调试和一次放弃；
- **星数不等于活跃度**：总星数只记录历史，最近的提交、issue 响应和 release 节奏才是现在时；
- **星数不等于适合你**：一个为大规模团队设计的框架，对一个人写博客可能是纯负担。

但当成千上万人独立地做出同一个动作，这个动作仍然指向某种集体预期：大家认为“接下来会需要什么”。所以星榜是一张**注意力地图**——它不告诉你该去哪，但能告诉你路正在往哪个方向修。

本文数据来自 GitHub REST API 在 2026 年 11 月 19 日的快照，星数四舍五入到千位，正文以万为单位。这个领域一周就能涨几千星，数字看趋势即可。

## 二、三层地图

把这次抓到的项目按“它解决哪一层的问题”摆开，大致是三层：

``` mermaid
flowchart TB
    subgraph L1[入口层]
        A[编码 Agent]
        B[个人 Agent]
        C[工作流工作台]
    end
    subgraph L2[能力层]
        D[编排框架]
        E[工具与抓取]
        F[记忆]
    end
    subgraph L3[底座]
        G[模型与推理引擎]
        H[本地运行与界面]
    end
    A --> D
    A --> E
    A --> F
    B --> F
    C --> D
    D --> G
    E --> G
    F --> G
    G --> H
```

这张图有几个值得注意的地方：入口层最热闹，能力层最拥挤，底座最安静。星数的增量集中在入口与能力两层，而底座的总星数依然庞大——这构成了后面所有判断的背景。

## 三、新面孔：一年长出来的高星带

先看最扎眼的一组。它们大多在 2026 年才进入大众视野，却已经排进了全站 AI 项目的前列：

| 项目 | 星数 | 它是什么 |
|---|---|---|
| morluto/rea | 46.8 万 | 用 Agent 做逆向工程，从 App 行为一路下探到原生二进制 |
| openclaw/openclaw | 39.5 万 | 全平台个人 Agent，主打“真的会干活” |
| obra/superpowers | 32.0 万 | Agent 技能框架与软件开发方法论 |
| affaan-m/ECC | 30.6 万 | harness 性能优化系统，覆盖技能、记忆、安全与研究流程 |
| deepseek-ai/deepseek-harness | 28.4 万 | DeepSeek 的插件化 harness，“一切皆插件” |
| NousResearch/hermes-agent | 26.4 万 | 强调随使用一起成长的 Agent |
| DietrichGebert/ponytail | 19.4 万 | 一套让 Agent 像“最懒的资深工程师”那样思考的技能 |

七个项目里，有五个直接和 harness、技能、记忆有关：superpowers 是技能框架，ECC 优化 harness，deepseek-harness 把插件化做到极致，ponytail 是一套克制的编码技能，hermes-agent 强调成长。真正算“应用”的只有 rea 和 openclaw。

这组名单本身就是一个结论：**2026 年最稀缺的不是模型，而是让模型稳定干活的工程层**。rea 登顶还说明另一件事——当 Agent 被放进一个有明确反馈的领域，它能创造的价值远大于在开放对话里聊天。逆向工程恰好是这种领域：有二进制、有行为、有可验证的结果。

## 四、入口层：编码 Agent 与工作台

入口层是用户直接接触的那一层，也是竞争最激烈的一层。编码 Agent 的阵容：

| 项目 | 星数 | 形态 |
|---|---|---|
| anomalyco/opencode | 22.8 万 | 开源编码 Agent，终端、编辑器与桌面共用一套后台 |
| anthropics/claude-code | 15.6 万 | 终端里的编码 Agent |
| openai/codex | 13.6 万 | 轻量级终端编码 Agent |
| stablyai/orca | 12.9 万 | 用你自己的订阅编队运行多个编码 Agent |
| google-gemini/gemini-cli | 10.9 万 | 把 Gemini 带进终端的开源 Agent |
| OpenHands/OpenHands | 9.4 万 | 面向自主开发的 Agent 平台 |
| cline/cline | 7.2 万 | 以 IDE 扩展和 SDK 形态存在的编码 Agent |

一个值得玩味的数字：开源编码 Agent 的代表 OpenCode 已经到 22.8 万，超过了 Claude Code 的 15.6 万。这不等于“开源更好用”——官方 CLI 在模型、权限和生态整合上仍有优势。它说明的是这个品类的需求结构：**开发者希望编码 Agent 可自托管、可换模型、可被自己的脚本和规矩改造**。OpenCode 的插件与技能机制，正好接住了这部分需求。

工作台是另一条路线：n8n 21.1 万、dify 16.1 万、langflow 15.7 万，把编排做成可视化界面，面向不想写代码的业务用户。两条路线的共同点在于，它们都把“调用模型”降级为流程里的一个节点——真正的价值在节点之间的连接和约束。

顺带提一句 AutoGPT：18.8 万星，仍在榜单前列，但更像一座纪念碑。它证明了自主 Agent 的想象空间，也证明了纯自主路线在工程上的边界。今天活得好的是“有约束的循环”，不是“放手让它自己跑”。

## 五、能力层：编排、工具与记忆

能力层不直接面对用户，却决定了 Agent 能走多远：

| 项目 | 星数 | 分类 | 作用 |
|---|---|---|---|
| firecrawl/firecrawl | 20.3 万 | 工具 | 把网页变成 Agent 可用的结构化数据 |
| langchain-ai/langchain | 15.0 万 | 编排 | Agent 工程平台与组件库 |
| Shubhamsaboo/awesome-llm-apps | 14.5 万 | 示例 | 上百个 Agent 与 RAG 应用范例 |
| browser-use/browser-use | 12.1 万 | 工具 | 让 Agent 操作浏览器 |
| thedotmack/claude-mem | 11.8 万 | 记忆 | 跨会话持久上下文，压缩后按需注入 |
| mem0ai/mem0 | 6.9 万 | 记忆 | 即插即用的 Agent 记忆基础设施 |
| microsoft/autogen | 6.2 万 | 编排 | 多 Agent 编程框架 |

记忆层是这份榜单里最值得单独说的一块。claude-mem 的做法是记录会话、用 AI 压缩、在需要时注入相关上下文；mem0 把自己定位成“drop-in”的记忆基础设施。它们解决的都不是“存聊天记录”，而是“把过去的结论变成下一次可检索的输入”。

这和刚发布的《[Harness 工程](/ai/2026-11-15-harness-engineering/)》里讲的存档降级、分层记忆是同一件事的产品化：上下文是 cache，磁盘才是存储，记忆的价值在于“什么时候取回什么”，而不是“存了多少”。

## 六、底座与学习资源

再往下是底座。它们不再是新闻主角，但星数依然稳居前列：

| 项目 | 星数 | 定位 |
|---|---|---|
| ollama/ollama | 18.8 万 | 一键在本地运行开源模型 |
| huggingface/transformers | 16.9 万 | 模型定义与训练的行业基石 |
| AUTOMATIC1111/stable-diffusion-webui | 16.5 万 | Stable Diffusion 的网页界面 |
| open-webui/open-webui | 15.9 万 | 可自托管的 AI 聊天与工作台 |
| ggml-org/llama.cpp | 13.6 万 | C/C++ 本地推理引擎 |
| vllm-project/vllm | 9.7 万 | 高吞吐推理服务引擎 |
| infiniflow/ragflow | 9.4 万 | 面向 RAG 与 Agent 的数据层 |

它们像水电煤：平时没人讨论，一旦停供所有人都难受。基础设施的寿命，通常比应用层长得多。

学习资源则出现了一个方向性变化。prompts.chat 仍是最大的提示词集合，17.8 万星；Prompt Engineering Guide 8.0 万；但增长叙事已经转向“从零构建 AI 工程”，ai-engineering-from-scratch 拿到 7.9 万星。读者关心的从“怎么问”变成了“怎么造”。

## 七、三条趋势判断

把上面的数字连起来看，能看到三条比较清楚的线。

**判断一：注意力从模型转向 harness。** 增量最大的项目几乎都不训练模型，它们做的是技能、编排、记忆、编码 Agent 和运行框架。模型能力在头部厂商之间趋于同质化之后，差异化的战场自然上移到了“怎么组织模型干活”。这和《[AI 的自我改进](/ai/2026-11-08-AI的自我改进/)》里的判断互为印证：模型是引擎，闭环在引擎之外。

**判断二：记忆独立成赛道。** claude-mem 与 mem0 加起来不到 20 万星，绝对数不算顶流，但方向很明确——Agent 要从“单次工具”变成“长期同事”，跨会话的状态是绕不过去的坎。谁能把“记住什么、何时取回、如何遗忘”做好，谁就拿到了下一阶段的门票。

**判断三：技能与纪律成为新象限。** superpowers、ECC、deepseek-harness、ponytail 这些项目，本质上都在给 Agent 装纪律：什么时候先规划、什么时候该少写代码、哪些操作必须门控、哪些经验要沉淀成技能。这个象限的规模化是最近一年才发生的事，现在却占据了新晋榜的大半。它回答的是一个很实际的问题：模型都一样聪明时，为什么有的 Agent 好用、有的难用？答案在 harness 和技能里。

## 八、榜单的盲区与选型动作

星榜有三个必须知道的盲区：

1. **总量会被历史绑架**：老项目躺在过去的成绩上，新项目需要时间积累，单看总星会低估新东西；
2. **增速会被传播放大**：一篇爆款文章、一次大佬转发，就能让星数曲线陡峭，但它不改变代码质量；
3. **收藏是最廉价的表态**：点星只需要一秒，跑通一个项目可能要一个周末，两者之间的转化率很低。

所以真正选型时，我建议做三个动作：

- **按层找，不按榜找**：先确定自己缺的是入口、能力还是底座，再去对应层里挑，而不是直接选总榜第一；
- **做一次四问体检**：最近一次 release 是什么时候、issue 有没有人回、文档能不能在 30 分钟内跑通、权限与数据边界是否清楚；
- **组合优于单点**：一个顺手的 Agent，通常是 harness、技能、记忆、工具和验证器的组合。以我自己为例，OpenCode 提供循环，superpowers 提供方法论，MCP 接工具，只读验收 agent 兜底——单看任何一个都不是榜单第一，组合起来才解决实际问题。

## 九、小结

这篇没有讲新原理，它做的是给这个系列配一张坐标图：原理告诉你为什么会这样，星榜告诉你这些东西现在落在哪里。

三句话带走：

- **星榜是注意力地图，不是路线图**：它标出人群的方向，不替你决定目的地；
- **基础设施的寿命长于应用**：底座项目不性感，但它们是所有性感的来源；
- **增长最快的象限是“让 Agent 稳定干活”**：模型负责聪明，工程负责可靠，后者才是 2026 年真正卷的地方。

地图画到这里，路线还是得自己走。下一篇，也许会从这张地图上的某个点出发，做一次实测。
